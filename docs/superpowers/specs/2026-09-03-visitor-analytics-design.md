# 방문자 통계 및 포스트 클릭 기록 설계

## 목표

개인정보를 수집하지 않는 GoatCounter를 사용해 `groovallstar.github.io`의 페이지 조회와 포스트 링크 클릭 횟수를 관리자 전용 대시보드에서 확인한다. 블로그에는 공개 방문자 수나 관리자 화면을 추가하지 않는다.

## 범위

포함하는 기능은 다음과 같다.

- 모든 운영 페이지의 경로별 방문 집계
- 홈, 카테고리, 태그 목록에 표시되는 포스트 링크의 클릭 집계
- 같은 방문자의 반복 클릭 집계
- 로컬 개발 환경의 통계 제외
- 관리자 전용 GoatCounter 대시보드 사용

개별 방문자를 식별하거나 방문 경로를 개인 단위로 연결하는 기능, 공개 조회 수 표시, 자체 관리자 페이지, API 기반 통계 재가공은 범위에서 제외한다.

## 서비스 선택

GoatCounter의 호스팅 서비스를 사용한다. 개인 블로그의 합리적인 공개 사용은 무료이고 쿠키나 브라우저 저장소에 추적 식별자를 남기지 않으며, 기본 페이지 조회와 HTML 속성을 이용한 클릭 이벤트를 모두 지원하기 때문이다.

Plausible은 같은 요구사항을 충족하지만 무료 체험 이후 유료다. Cloudflare Web Analytics는 무료이고 개인정보 친화적이지만 사용자 지정 클릭 이벤트를 지원하지 않아 선택하지 않는다.

## 사전 조건

사용자가 GoatCounter 계정을 직접 생성하고 `groovallstar.github.io`를 사이트로 등록한다. 계정 생성에는 이메일과 비밀번호가 필요하므로 자동화하지 않는다. 구현에는 GoatCounter가 발급한 공개 사이트 코드만 사용하며 비밀번호와 API 키는 저장소에 기록하지 않는다.

## 구성과 데이터 흐름

1. Jekyll이 `_config.yml`의 GoatCounter 사이트 코드와 운영 호스트를 읽는다.
2. 공통 레이아웃이 분석 include를 모든 페이지에 삽입한다.
3. 브라우저가 운영 호스트에서 페이지를 열면 GoatCounter 스크립트를 비동기로 로드한다.
4. GoatCounter가 현재 페이지의 경로와 제목을 페이지 조회로 집계한다.
5. 사용자가 목록의 포스트 링크를 클릭하면 링크에 선언된 이벤트 이름과 글 경로를 GoatCounter로 전송한다.
6. 링크 이동은 분석 요청과 독립적으로 계속 진행된다.

로컬 호스트와 비운영 도메인에서는 추적 스크립트를 로드하지 않는다. GoatCounter 요청이 차단되거나 실패해도 사이트 표시와 링크 이동에는 영향을 주지 않는다.

## 파일 변경

### `_config.yml`

GoatCounter 공개 사이트 코드와 운영 호스트를 추가한다. 계정 비밀번호와 API 키는 추가하지 않는다.

### `_includes/analytics.html`

운영 환경에서만 GoatCounter 스크립트를 비동기로 로드한다. 사이트 코드가 비어 있으면 아무것도 출력하지 않는다.

### `_layouts/default.html`

페이지 본문과 독립적인 위치에서 분석 include를 한 번만 호출한다.

### `_includes/post-entry.html`

포스트 카드 링크에 `data-goatcounter-click`, `data-goatcounter-title`, `data-goatcounter-no-session` 속성을 추가한다. 이벤트 경로는 포스트 URL에서 결정하고 제목은 포스트 제목을 사용한다. 반복 클릭도 집계한다.

## 개인정보와 데이터 최소화

블로그 코드는 페이지 경로, 페이지 제목, 클릭 이벤트 이름, 포스트 제목만 GoatCounter에 전달한다. 이메일, 이름, API 키, 임의 사용자 식별자, localStorage 값, URL 쿼리 문자열은 전송하지 않는다.

GoatCounter의 개별 페이지뷰 저장 옵션은 켜지 않고 기본 집계 모드를 사용한다. 운영자가 자신의 방문을 통계에서 제외하고 싶을 때는 GoatCounter가 제공하는 브라우저별 차단 기능을 사용한다.

## 오류 처리

- 사이트 코드가 없으면 분석 태그를 렌더링하지 않는다.
- 로컬 개발 서버에서는 분석 스크립트를 로드하지 않는다.
- 외부 스크립트는 비동기로 로드해 렌더링을 막지 않는다.
- 분석 요청 실패나 광고 차단기 차단이 링크 기본 동작을 가로막지 않는다.
- 이벤트 전송을 기다리기 위해 인위적으로 페이지 이동을 지연하지 않는다.

## 검증

### 정적 검증

- Jekyll 프로덕션 빌드가 성공한다.
- 운영 설정으로 생성한 모든 페이지에 GoatCounter 스크립트가 한 번만 존재한다.
- 포스트 목록 링크에 글별 클릭 이벤트 속성이 존재한다.
- 사이트 코드가 비어 있을 때 분석 스크립트가 생성되지 않는다.
- 로컬 호스트용 결과에서 추적이 비활성화된다.

### 브라우저 검증

- 운영 홈페이지와 포스트 페이지가 정상적으로 표시된다.
- 분석 스크립트가 실패하거나 차단돼도 포스트 링크가 정상 이동한다.
- 테스트 방문 뒤 GoatCounter 관리자 화면에 페이지 조회가 기록된다.
- 테스트 포스트 클릭 뒤 해당 글의 클릭 이벤트가 기록된다.

### 배포 검증

- GitHub Pages 배포 작업이 성공한다.
- 운영 홈페이지와 포스트 URL이 HTTP 200으로 응답한다.
- 배포된 HTML에 올바른 GoatCounter 사이트 코드와 클릭 이벤트가 포함된다.

## 완료 기준

- GoatCounter 관리자 화면에서 운영 페이지 조회와 포스트 클릭 횟수를 구분해 확인할 수 있다.
- 방문자의 쿠키나 브라우저 저장소에 추적 식별자를 만들지 않는다.
- 로컬 개발 방문은 집계하지 않는다.
- 분석 서비스 장애가 블로그 사용에 영향을 주지 않는다.
- 저장소에는 공개 사이트 코드 외의 GoatCounter 자격 증명이 존재하지 않는다.
